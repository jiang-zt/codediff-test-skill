# 输入确认

## 目标

在执行测试影响分析前，收集足够信息，明确分析边界和输出目标。不要在输入不清时直接生成结论。

## 必要信息

优先确认以下信息：

1. Diff 来源
   - GitHub PR URL，或
   - `repo={owner}/{repo}, pr={number}`，或
   - `repo={owner}/{repo}, base={branch}, head={branch_or_sha}`
2. 本地项目路径
   - 推荐提供 Java/Spring 项目的本地 checkout 路径。
   - 如果没有本地路径，只能基于 GitHub patch 做保守分析。
3. 当前工作目录与 featureID
   - 确认当前工作目录是否为用户项目根目录。
   - 优先从 head 分支最后一段提取 `featureID`。
   - 如果没有 head 分支，使用当前本地日期时间生成，例如 `analysis-20260529-114530`。
   - 如果没有 head 分支但有 PR 编号，可使用 `pr-<number>-20260529-114530` 方便追溯。
   - 将 `/`、空格和特殊符号替换为 `-`，确保可作为文件夹名。
4. 输出类型
   - 中文 Markdown 测试影响分析报告
   - Markdown + Postman 集合
   - Markdown + 其他测试资产草稿
5. 可选需求与接口文档
   - PRD、需求文档、验收标准、接口文档、OpenAPI/Swagger。
   - 可以是本地路径，也可以是链接。
   - 确认是否允许访问链接，以及是否需要登录或权限。
   - 未提供文档时不阻塞分析，但需要在报告中说明边界。
6. 可选测试上下文
   - API base URL
   - 鉴权方式或 token 占位符
   - 测试环境限制
   - 已知高风险模块或核心业务流程
   - 是否重点关注兼容性、数据库、权限、性能或回归范围

## 默认假设

如果用户未说明，按以下假设继续，但必须在报告中写明：

- 项目类型：Java Spring Boot / Spring MVC。
- 默认交付物：中文 Markdown 测试影响分析报告。
- 可选资产：只有识别到 Controller 接口且用户需要时才生成 Postman。
- 业务仓库默认只读，不修改代码、不新增测试。
- 没有本地项目路径时，所有调用链、鉴权、数据含义和业务规则结论均降低置信度。
- 如果在用户项目根目录运行，默认输出到 `diff/<featureID>/` 和 `output/<featureID>/`。
- PRD、需求文档、接口文档为可选输入；未提供时不阻塞分析。

## 输入关卡 Harness（关卡检查）

进入下一步前检查：

```text
□ PR URL 或 repo/base/head 已明确
□ 本地项目路径已明确，或已记录“无本地上下文”
□ 当前工作目录是否为项目根目录已确认
□ featureID 已确定；没有 head 分支时已使用当前日期时间兜底
□ 是否提供 PRD / 需求 / 接口文档已确认；未提供时已记录边界
□ 输出类型已明确
□ 是否生成文件已得到用户授权，或用户已明确要求生成
□ 关键假设已记录
```

## 分析前摘要

运行工具前，先给出简短摘要：

```text
Diff 来源：...
仓库：...
PR / base-head：...
本地项目路径：可用 / 不可用
工作目录：...
featureID：...
输出目录：diff/<featureID>/，output/<featureID>/
需求 / 接口文档：已提供 / 未提供
输出目标：...
关键假设：...
```
