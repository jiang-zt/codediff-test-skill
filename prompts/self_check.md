# 交付前自检

## 目标

在交付测试影响分析结果前，执行一次完整自检，确保报告有证据、有边界、有不确定项，且符合中文测试团队使用习惯。

## 总体检查

```text
□ 已记录 PR URL 或 repo/base/head
□ 已记录 featureID；无 head 分支时已用当前日期时间兜底
□ diff 文件位于 diff/<featureID>/diff.json，除非用户指定了其他目录
□ 分析产物位于 output/<featureID>/，除非用户指定了其他目录
□ 已说明是否使用本地项目代码上下文
□ 已说明是否提供 PRD / 需求 / 接口文档
□ diff.json 已生成或失败原因已说明
□ impact.json 已生成或无法生成原因已说明
□ 报告为中文 Markdown
□ 未修改业务仓库，除非用户明确要求
```

## 证据检查

```text
□ 每个受影响接口都有 Controller 注解、方法或用户确认作为证据
□ 每条重要测试建议都引用了变更文件、方法、接口或 DTO
□ Service 风险已尽量回溯到调用入口
□ DTO、SQL、配置、依赖、测试变更没有被忽略
□ 如提供文档，文档中的验收标准、接口契约或字段规则已转化为测试点
□ 如未提供文档，报告没有引用虚构的文档依据
□ 文档和代码不一致时已列入人工确认项
□ 工具无法识别的内容已由 agent 阅读本地代码补充，或写为不确定项
```

## 报告质量检查

```text
□ P0/P1/P2 回归范围清晰
□ P0 项优先展示
□ 不确定项与人工确认项单独列出
□ 没有编造接口、字段、业务规则、鉴权或测试数据
□ 没有只有泛泛建议、缺少证据的结论
□ 如果缺少本地项目路径，报告中已明确分析局限
□ 如果未提供 PRD / 需求 / 接口文档，报告中已明确分析边界
```

## 可选资产检查

```text
□ Postman 集合只包含已识别或用户确认的接口
□ 未写入真实 token、cookie、密钥
□ 请求体未知字段使用占位符
□ 业务断言未知时没有编造
□ JSON 可解析，可导入 Postman
```

## 失败处理

如果任一关键项失败：

- 能修正的，先修正报告或资产。
- 不能修正的，在交付说明中列出限制。
- 不要把不确定内容包装成确定结论。
