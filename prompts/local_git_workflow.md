# 本地 Git 变更分析工作流

目标：读取本地已提交代码的差异及相关上下文，按后附的统一交付规范生成中文分析文档与可实操参考的测试用例。分析由客户端模型完成。

## 1. 确认输入与分析场景

- 输入为用户授权的仓库根目录 repo_path、head 和 base。base 默认 master；不存在时询问实际基线，不擅自替换为 main。
- 此入口使用 mode=test，服务于本地变更的测试分析。输出维度与 GitHub 入口相同。
- output_dir 仅取用户在对话中明确指定的保存目录；尚未提供时可继续分析，保存前询问。

## 2. 获取 diff 与核对版本

- 调用 get_code_diff(repo_path, head, base)，检查 ok、base_sha、head_sha、has_changes、files 和 limitations。
- 只比较两个已提交树，不包含工作区、暂存区或未追踪文件；不自动 checkout、fetch 或 pull。
- 获取失败时说明错误，不把空 diff 或缺失对象解释为无风险。
- 未连接 MCP 时明确说明。仅经用户允许，才可用 CLI 降级，并注明不属于 MCP 调用验证。

## 3. 补充完整代码与依赖

- 使用客户端已有且获准的只读代码能力，读取 head_sha 对应的完整变更方法及相关接口、测试和配置；必要时读取 base_sha 的旧代码。
- 优先读取固定提交内容，例如 git show SHA:路径；不以当前工作区内容替代对应提交。不能读取固定版本时列出证据缺口。
- 删除文件读取 base_sha；重命名旧文件使用 previous_path。调用链仅在实际读取的代码范围内确认。
- 初轮补充最多10个文件，再根据风险决定是否扩大；未覆盖文件及依赖必须列明。

## 4. 对齐统一交付参数

- save_analysis_report 的 mode=test，repo=实际仓库根目录，base_sha/head_sha=本次工具返回的固定 SHA。
- 使用后附的统一交付规范完成分析、用例设计与保存；不另设本地版输出标准。
