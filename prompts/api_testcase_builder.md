# 接口测试用例建议

## 目标

基于 `output/<featureID>/impact.json` 和可选的 PRD / 需求 / 接口文档生成中文接口测试用例建议。用例建议应服务于测试人员执行或补充自动化测试，不要只写泛泛的“加强测试”。

## 用例字段

每条用例建议至少包含：

- 优先级：P0 / P1 / P2
- 测试对象：接口、模块、Service 方法或数据访问点
- 测试场景
- 前置条件 / 测试数据
- 请求参数或数据准备
- 预期断言
- 证据：文件路径、方法名、接口路径或 diff 来源
- 文档依据：PRD、需求文档或接口文档章节，未提供时可写“未提供”
- 备注 / 不确定项

## Controller 接口规则

对每个受影响 Controller 接口，优先生成：

- P0：正常请求成功路径。
- P0：必填参数缺失、非法值、边界值。
- P0：核心业务状态流转或写操作结果校验。
- P1：鉴权、权限、租户隔离。
- P1：重复提交、幂等、并发或回滚场景，尤其是 create、update、delete、pay、refund、order 等语义。
- P2：请求/响应 DTO 变化导致的老客户端兼容性检查。

如果提供接口文档，应额外覆盖：

- 文档定义的状态码和错误码。
- 文档要求的 header、鉴权、租户字段。
- 文档中的请求/响应字段必填和格式要求。
- 文档列出的异常返回和边界场景。

## DTO 变化规则

字段或校验注解变化时，生成：

- 必填字段缺失。
- 空字符串、空集合。
- 长度边界。
- 枚举、状态值非法。
- 数字上下界。
- 日期时间格式、时区、开始结束时间关系。
- 字段删除、重命名或类型变化导致的兼容性检查。

## Service 变化规则

Service 方法变化时，生成：

- 主业务分支。
- 新增条件分支。
- 异常和失败路径。
- 事务回滚或补偿路径。
- 外部系统调用失败、超时或返回异常。
- 状态流转前后置约束。

如果提供 PRD 或需求文档，应将验收标准逐条转化为测试场景，并标注文档依据。

## Mapper / 数据库规则

数据访问变化时，生成：

- 空结果。
- 单条和多条结果。
- 分页、排序、筛选条件组合。
- 历史数据兼容。
- 插入、更新、删除后的持久化校验。
- 事务一致性和重复写入风险。

## 禁止事项

- 不要编造请求体、鉴权方式、业务枚举或成功断言。
- 无法确认的数据用占位符，并标注“需人工确认”。
- 不要生成没有证据来源的测试建议。
- 未提供 PRD / 需求 / 接口文档时，不要编造文档验收标准。

## 用例关卡 Harness（关卡检查）

输出用例建议前检查：

```text
□ 每条 P0 用例都有直接证据
□ 用例证据来自 output/<featureID>/impact.json 或本地代码阅读结果
□ 如提供文档，验收标准和接口契约已转化为测试场景
□ 如未提供文档，用例没有引用虚构的文档依据
□ DTO 变化已覆盖合法、非法、边界和兼容性
□ 写操作接口已考虑数据落库或状态变化
□ 权限、租户、鉴权不可见时已写为人工确认项
□ 用例描述为中文，可被测试人员直接理解
```
